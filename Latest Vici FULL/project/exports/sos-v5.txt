SOS Workflow
Full Branching Logic for a Pornography-Urge Intervention Flow
CORE PRODUCT PRINCIPLE
The stronger the urge, the less thinking the user should have to do. High-intensity states get action first; reflection comes later.
This document defines the decision logic, response modules, branch copy, combination rules, edge cases, and implementation model for a personalised SOS workflow.
The goal is not to generate hundreds of hand-written combinations. The goal is to assemble a small number of high-quality modules in the right order, so each session feels specific to the user’s actual situation.
IMPLEMENTATION BRIEF
Implement this as the app’s SOS flow for someone who opens it during an active urge. Assume attention is limited and the user may be tired, alone, sexually triggered, or already close to acting. It should feel like a calm coach taking control of the next few minutes — not a survey, lecture, or therapy worksheet.
Use the answers to change what the app asks the user to do, not just the wording. Intensity controls urgency; location controls what is safe and possible; feelings and triggers explain what the user is trying to regulate. At high intensity, change the body or environment first and reflect later.
Repeated use should still feel fresh. Keep the essential safety move consistent when it matters, but rotate the follow-up challenge, avoid recently shown actions, and filter every suggestion for time, setting, privacy, and physical safety.
Recommended response hierarchy:
1) Interrupt the immediate behaviour
2) Change the environment
3) Regulate the underlying state
4) Remove the trigger
5) Address the real problem after the urge falls

1. Design Rules
Rules That Every Branch Should Obey
Action before analysis at high intensity. A 5/5 user should never receive a paragraph before the first concrete action.
One screen = one job. Do not mix “leave the room,” emotional interpretation, education, and journaling on a single emergency screen.
Environment beats willpower. If the context is high-risk, change the context before asking the user to “resist.”
Pornography is the target behaviour; sexual arousal itself is not framed as dangerous or shameful.
Use specific verbs: stand up, close it, lock the phone, walk to the kitchen, message someone. Avoid generic “distract yourself” advice.
Never punish honesty. If the user says they already opened porn or already slipped, the app becomes more useful, not more judgmental.
The response should get shorter as urgency rises. Choice sets should narrow as urgency rises.
Do not make the user solve the underlying life problem during the urge. First get the urge down; then offer a next step for the real problem.

5A. Challenge Rotation &amp; Safety
Variety should come from the action pool, not from adding minor location categories.
Rule
Implementation
Why
Mandatory move + variable challenge
Some locations keep the same first move every time (bed → Get up; bathroom → Leave). After that, select one challenge from the eligible pool.
Preserves the strongest behavioural rule without making repeat sessions feel identical.
Safety filter before novelty
Filter by leaving-home safety, time of day, mobility/health constraints, privacy/discretion, and whether movement is possible BEFORE random selection.
Novelty never outranks safety.
Anti-repeat window
Do not show the exact same action from the previous 3 SOS sessions if another eligible option exists. Prefer a different action family from the previous session.
The fifth SOS should not read like the first.
Weighted rotation
Among safe candidates, prefer actions the user has completed before and that were followed by a larger intensity drop, while retaining some novelty.
Personalisation becomes evidence-based without becoming deterministic.
Skip without penalty
Every challenge has “give me another” or an equivalent skip. Skipped actions are down-ranked, not treated as failure.
A challenge can be wrong for reasons the app cannot observe.
No exhaustion requirement
Exercise can feel demanding, but stop at pain, dizziness, or form breakdown. Do not require true muscular failure.
Keeps “hard challenge” energy without unnecessary physical risk.

Default challenge
Move first, then choose one eligible three-to-five-minute challenge from the location pool. No introspection is required.

15. Learning From Prior SOS Sessions
Personalisation Should Change Ranking, Not Invent Clinical Claims
Learn which locations recur before slips (for example, bed + late night) and surface preventive advice earlier.
Learn which interventions the user actually completes and which are skipped.
Learn which alternatives reduce intensity most often for that user.
If the same trigger repeats, suggest a permanent friction change after the SOS: app limit, phone charging location, unfollowing content, door-open rule, bedtime routine.
Never tell the user “this is your real cause” from a few sessions. Phrase patterns probabilistically: “this seems to show up often when…”

19. QA Checklist
Before Shipping the SOS Decision Engine
5/5 Never shows a long paragraph before a concrete action.
No branch tells a user to stay in a high-risk private location when moving is practical.
No branch shames sexual arousal or treats having a thought as a relapse.
“Already opened” branch first breaks access.
“Already slipped” branch does not imply the rest of the day is ruined.
Tired users are not told to do stimulating activities late at night.
Public/work branches are discreet, and strenuous or conspicuous challenges are filtered out.
Leaving-home challenges are never required when safety is unknown, it is late, or the user marks leaving as unsafe.
Underlying relationship/money/work advice is delayed until the urge is lower.
Every action can be completed safely in the user’s stated context or has an indoor / low-mobility fallback.
Reassessment can re-escalate the workflow if intensity increases.
Analytics can distinguish shown actions from completed actions, and the selector can suppress recently repeated action IDs.

North-star test
At every screen ask: “Given what we know right now, what is the smallest action most likely to make pornography harder to access or less attractive in the next 60 seconds?” If the screen does not help answer that, it probably does not belong in the emergency flow.
