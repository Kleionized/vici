# Vici UI 2 — decisions

Every call made without asking, with the reason. Numbered in the order made.

**D1 · Design source.** `./Vici UI 2` (exact on-disk name, capital V, U, I; one match from the repo root). Its `README.md` names `Vici SOS.dc.html` as the primary design. The README also says not to render or screenshot the files; the brief for this run asks for exactly that, and the brief wins.

**D2 · Status bar and home indicator are out of the pixel count.** Every frame draws its own status bar (time in Lato 17/700, Lato glyph widths, hand-drawn signal, wifi and battery icons) and a 139×5 home indicator at y 839. On the device both are drawn by iOS in SF, over the app. The app cannot draw them, so `scripts/pixel-diff.mjs` blanks `0,0,393,54` and `120,832,153,16` (points) in both images before comparing. The simulator's status bar is still overridden to the frame's time so the side-by-sides read the same.

**D3 · Device.** The frames are 393×852 (`width:393px; height:852px` on every `[data-screen-label]`, except the four `393×667` small-phone checks and the 425-wide illustration cards). iPhone 16 is 393×852 @3x, so a new simulator `iPhone 16 – Vici UI 2` (iOS 26.5, UDID 741DA6CE-82DA-4A8B-A1D8-12DD7558A0C5) was created. Its screenshots are 1179×2556, the same size as a design render at deviceScaleFactor 3.

**D4 · Design renders use a frozen clock.** The SOS and Relapse canvases read `Date.now()` for the status bar time, an urge's elapsed timer and the breathing phase. Renders install Playwright's clock paused at 2026-10-21 09:41:00 and advance it exactly 2,000 ms after load, so every render is reproducible. The harness fixtures use the values those renders show.

**D5 · Fonts in renders.** The canvases load Lato from Google Fonts. The renderer answers that request with `@font-face` rules pointing at the TTFs the app bundles (`@expo-google-fonts/lato` 400, 700, 900, 700 italic, 400 italic), so no diff can come from a different font file.

**D6 · The design bundle was committed in the baseline.** The only uncommitted work on the starting branch was the new `Vici UI 2/` folder (212 MB, mostly reference uploads). The brief says to commit uncommitted work as the baseline, and the repo already tracks the previous design bundle (`Vici Overhaul/`), so it went in with the baseline commit.

**D7 · The SOS is rebuilt, not restyled.** `Vici SOS.dc.html` draws a different flow from the app's (rate → place → what's feeding it → what you're putting off → feeling → one task from a 120-task library → a hub to do it in → check → another task? → summary). The old flow's boards (intro, three moves, response boards, reassess, afterward, the breathe/tap/odd/wave stages, the relief board) and the separate urge hub have no counterpart in the new bundle. The brief makes the design the authority on screens; the flow a screen sequence implies comes with it. What the app owns is kept: the urge session that survives the app being closed (`urgeSession.ts`, D461), one `urge_rode_out` event per urge written in the background, the post-pending flag, swipe-back off. New code: `src/components/urge/sos.tsx`; `/urge` renders it; `/urge-hub` and `/rough-first90` redirect to it.

**D8 · The task library and its rules are the bundle's.** `src/content/sosLibrary.data.ts` and `src/content/sosViz.ts` are generated from `sos-library.js` and `sos-viz.js` (`scripts/vici-ui-2/gen-sos.mjs`); `src/content/sosLibrary.ts` ports `ctx`, `needs`, `eligible`, `score`, `jitter` and `next` line for line. The canvas's frames use tie-break seed 7; a real urge picks a seed from 1–997 as the canvas's live frame does. `heading()` is defined in the library but no frame draws it, so it is not ported.

**D9 · What the urge event carries.** severity = the first read (1–5 → 2·4·6·8·10, the app's existing mapping); severityAfter = the second read the same way, or 0 for "It's gone"; durationSeconds = time from the urge's start to the summary; trigger = the picked reasons except "I don't know", joined " · "; whatHelped = the title of the task on screen; precedingState = place, first feeling, reasons. "What helped before" reads these back: past urges whose whatHelped is a task title and whose second read was lower (and not gone), newest first, three at most, not the task on screen — the canvas's own filter (`h[3] < h[2]`, `slice(0, 3)`).

**D10 · Pages the hub shows.** The canvas shows "What helped before" only when there is history (`pages()`). The pledge page is shown on the same rule: only when the user has a pledge of their own (`standingPledge`, D475). Without one the canvas's sample line would be presented as the user's words.

**D11 · ✕ mid-flow.** The canvas's ✕ resets the frame. In the app it leaves. A session that reached the check or "another task?" has been worked through and is logged as it stands before leaving; earlier, ✕ just ends the session (the old flow's rule, F4).

**D12 · The SOS tab opens a chooser.** `97 · SOS — Urge or Relapse` is new in `Vici UI 2`. It is `/sos`; the tab bar's SOS disc pushes it. "An urge" replaces it with `/urge`, "A relapse" with `/slip`.

**D13 · Line breaks.** The frames set headings in `text-wrap: balance` and paragraphs in `text-wrap: pretty`, which WebKit honours and iOS cannot express. `scripts/vici-ui-2/gen-wraps.mjs` records, from the WebKit renders, every such run that wraps: its words, size, box width and the lines WebKit drew. `wrapAs()` (src/lib/wrap.ts) gives a run back with `\n` at those breaks when it is laid out at the width the frame drew it at. At other widths the platform's own wrapping applies.

**D14 · Dev harness.** `src/app/dev/harness.tsx`, opened with `tideline://dev/harness?view=<screen>&state=<state>`. It returns a redirect to `/` when `__DEV__` is false, and nothing in the app links to it. Its fixtures (`src/dev/`) are the canvases' own presets; its clock stands at the renders' clock (D4).

**D15 · Canvas y on the device.** The kit placed canvas y 0 at the safe-area top minus 54 (D009). iPhone 16, the frame's own 393 × 852 phone, reports a safe-area top of 59, so every top-anchored element sat 5 pt low (measured on `01 · SOS — Rate the urge`: the heading, marks and bars 15 device px below the render, bottom-anchored pills exact). `useCanvasTop()` now subtracts 59 on phones whose inset is 59 or more (Dynamic Island) and 54 on the rest, so on iPhone 16 the frame's y is the screen's y and shorter-inset phones lay out as before. Today and Score computed the same offset by hand; they now call `useCanvasTop()`.

**D16 · Noise floor (calibrated on `01 · SOS — Rate the urge`, 0.022 %).** WebKit and iOS rasterise Lato with different anti-aliasing and round glyph advances differently. What remains when a screen matches: one-device-pixel fringes around glyph edges (mostly classed as anti-aliasing by pixelmatch, with scattered single red pixels), and right- or centre-aligned runs offset by at most one device pixel (⅓ pt) horizontally ("Very strong"). Glyphs along a line can also sit up to two device pixels apart by the line's end: measured in a text lab (`src/dev/TextLab.tsx`, `scripts/vici-ui-2/textlab.mjs`), WebKit and iOS give every string the same advance width to the thousandth of a point ("tool, textbook or material needed for" is 256.080 in both), so the drift is where each engine snaps glyphs to device pixels, not a width, spacing or kerning difference. Anything beyond that is a finding: a non-text edge offset by two device pixels or more, a text run whose start or width differs, a filled area of another colour, a different line break, a missing or extra element, a different stroke weight.

**D17 · What the relapse messages know.** The canvas picks a message from facts about the entry and the person. The app supplies: the hour and date (real), whether the person has completed a lesson (`known_prior_course_or_task_practice`, from lesson progress), and leaves "trying to sleep" unknown (the relapse flow does not ask it; the canvas's own default is "Unknown") and earlier quit attempts false (onboarding asks "Have you tried to quit before?" but the answer is not kept after onboarding). Messages that need those facts are then not chosen, which is the canvas's behaviour for an unknown fact. What has been shown is kept per account on the phone (`ACCOUNT_KEYS.relapseHistory`, cleared at sign-out) so messages do not repeat.

**D18 · Pages in the bundle that are not design sources.** `exports/Journey Campaign.html`, `exports/Lesson Detail.html` and `exports/Lesson Parts.html` are byte-identical to the previous bundle's, drawn in the earlier paper system (`#F4F3F0` ground, SF Pro), and contradicted by the canvases, which draw the same places in the dark Lato system. The designer's QA pages (`screenshots/*.html`, `gen/check.html`, `gen/preview-*.html`, 166 artboards) sample canvas frames during the design work, including frames from flows the canvases no longer draw (`SOS Settings`, `Cue Hue Picker`, `SOS Feeling Picker`, earlier task layouts). Each of these artboards gets a ledger row with status `SUPERSEDED` and the reason; none is implemented. `viz-preview.html` holds one SVG and no artboard.

**D19 · The relapse flow replaces the post-slip flow.** `Vici Relapse.dc.html` draws the relapse as When → What led up to it → Do you feel like watching again → one message → the relapse log. The old post-slip boards (98A–98L and the nineteen cards) have no counterpart in the bundle. `/slip` now runs the new flow; `/relapses` is `05 · Back in the app`; `/lapse` and `/relapse` redirect to `/slip`; the log chooser's relapse row opens `/slip`. Kept from the old flow: logging a relapse ends any urge in progress and queues the post-slip letter; the lapse is written as a `lapse` event with its moment as `createdAt` and what led up to it as `trigger` (joined " · ", which the log, insights and report read).

**D20 · Relapse entries are editable, so the backend gains one mutation.** The canvas saves the entry on "What led up to it?", lets Back return to it ("Save changes", `02F`), and reopens entries from the log. The backend could only create events. Added: an optional `relapse` record on events (`convex/schema.ts`, `relapseRecord`: when, date, time, approx, causes, skipped, watch, message, quote), `events:create` now returns the new id, and `events:update` changes the moment, trigger, preceding state and relapse record of the signed-in user's own event (owner-checked). The mock store does the same. The Convex deployment has not been pushed from this run: `npx convex deploy` is needed before a real build can save relapses.

**D21 · `paint-order` in the drawings.** 103 shapes in `sos-viz.js` (and some in the calendar and the chooser's drawings) use `paint-order="stroke"` to cut a dark outline into their edge. react-native-svg ignores the attribute and paints the stroke over the fill, which thinned every cut shape (05B · One task · Reading: 4.46 % → 0.16 %). The generators rewrite each such shape as its exact equivalent: a stroke-only copy, then the shape with its fill and no stroke (`scripts/vici-ui-2/svg.mjs`).

**D22 · Small-phone and larger-text checks.** `01F` and `04E` are 393 × 667 frames and `02G`, `04D` show the pages at `zoom: 1.25`. No simulator is 393 × 667, and `zoom` is not Dynamic Type, so these four (and their copies in `Email Login.dc.html`) cannot be diffed. They are verified by spec: the app hides the art when the page is shorter than 700 and keeps the foot fixed under a scrolling page, as the canvas does.

**D23 · One point of slack on pre-broken text.** With WebKit's breaks applied (D13), a line that fills its box to the last hundredth can still measure a hair wider on iOS and push its last word to a line of its own ("ask them / to", "item." alone on 03 · F06 and K09). `WrapText` (src/components/mono/WrapText.tsx) gives a pre-broken run one point of slack on the side it does not align to (right for left-aligned text, half a point each side for centred). Every break is explicit, so no line moves and none can wrap again.

**D24 · The hero drawings come from the screens.** The new canvases redraw most illustrations (shelf and floor grounding, grey props). The app canvas, the twelve week canvases and the SOS draw each `data-hero` id identically (once the canvas's `data-dc-tpl` marks are removed), but the illustration catalog (`Lesson Illustrations v4.dc.html`) holds other, mostly older drawings for 45 of its cards. The screens are what the app reproduces, so `src/content/heroes.ts` is regenerated from them (`scripts/vici-ui-2/hero-usage.mjs`, `gen-heroes.mjs`); `balloon` and `sneaker`, which no screen draws, keep the catalog's art. `91G · Urge Log — When` draws its own calendar, kept as `calendar2`; `route` is new and has no designer bounds, so its bounds are its measured paint. The designer's `gen/hero-bounds.json` is unchanged and still drives the lesson boxes and the Today crop, but 36 redrawn heroes paint past it (up to 47 units above), so the band `Hero` draws in is sized from the measured paint (`HERO_PAINT_Y`) as well.

**D25 · No zero letter spacing, anywhere.** React Native on iOS turns any `letterSpacing` into `NSKern`, and `NSKern = 0` switches the font's kerning off. The theme's text styles all set `letterSpacing: 0` by default, so every untracked line in the app was set without kerning: "You don’t have to keep going over it until" laid out 283.264 wide against WebKit's 280.048 (text lab, `src/dev/TextLab.tsx`; with no `letterSpacing`, iOS gives 280.048 exactly, and a tracked 0.4 keeps the kerning: 296.848). `tracking()` in `src/lib/theme.ts` now emits `letterSpacing` only when it is not zero, and the thirteen overrides that cancelled a variant's tracking with `0` use `undefined` instead.

**D26 · Characters Lato does not have.** Lato has no arrows (U+2190–21FF) or dingbats (✓ ★ ☆). The frames set every run in `'Lato', -apple-system, system-ui`, so WebKit draws "→" in SF Pro; iOS, given only a Lato family, picked a thin arrow from another face, narrower, which moved what followed it ("Strength 3 → 1" on 06E). `latoRuns()` (src/components/mono/fallback.tsx) draws each such character in the system face at the run's weight; `MonoText`, `WrapText` and the new screens' plain runs use it.

**D27 · Drawings are not clipped at their box.** The task and relapse drawings are `<svg>`s with `overflow: visible`, so full-bleed floors run past the 345-wide box (A03, G02 · Walk indoors). Native SVG clips at its own box. `VizArt` lays the drawing on a canvas 48 larger on every side with the viewBox widened by the same amount at the fitted scale, so the art lands where the box puts it and nothing past the box is cut. The hub's pager no longer clips vertically either: the frame's pager does not.

**D28 · Copy the bundle did not change stays as the owner wrote it.** On 10 Oct (commit 67ffb74a, "app copy: plain, direct voice…") the owner had the app's copy rewritten in a plainer voice, everywhere except lessons, notifications and letter bodies. `Vici UI 2` still carries the earlier wording for those lines, word for word as `Vici Overhaul` had it ("What should we call you?" / app: "What's your name?"; "All your data will be encrypted." / app: "Encrypted in transit and at rest."). The brief allows text from the design or the app, never invented; the design did not revise these lines and the owner did. So regenerated content is merged three ways (`scripts/vici-ui-2/merge3.mjs`): each generator is run on the previous bundle (the base) and on `Vici UI 2`; a value the new bundle changed (a position, a size, a hero, a line it rewrote) is taken from the new bundle, and a value it left as it was keeps the app's. Screens where this leaves the app's words in place show those words as the one difference in their diff; each is listed in the report as a copy difference, not a layout one.

**D29 · The keyboard is put away for a capture.** `03 · Name` draws its field focused (the caret in the field) and no keyboard: the keyboard is iOS's, like the status bar. The app focuses the field on arrival, so iOS raises its keyboard over half the board. The simulator's "connect hardware keyboard" setting was tried and is not honoured by this simulator build, so the harness (`blur` on a target, `src/dev/HarnessDriver.tsx`) dismisses the keyboard 1.2 s after opening such a board. The field then shows its placeholder without the caret: the 2 × 20 caret is the one mark of the frame left unmatched. The app's behaviour (autofocus) is unchanged.

**D30 · Ratings and rates are the app's arithmetic.** `28 · Your VICI rating` draws "842 of 1,000 · Starting point"; the app draws the owner's 0–100 recovery rating and "Starting score" (owner commits 9487e33d, 9 Oct, and a404a85e, 12 Oct, `.overhaul/decisions/deploy-rating.md`). `29 · The next 30 days` and `30 · One year from now` draw 9 of 30 days and 110 days; the app works both out from the frequency answered (13 of 30 and 158 for "A few times a week", D471). Data and logic are the app's, so these boards keep the app's numbers and words; the drawing around them (gauge, dot grids, positions) is the frame's.

**D31 · The paywall keeps its way out and its terms.** The frames' paywall draws "Restore" top right and no close, no renewal terms under the plans, "Terms · Restore" in the footer, and a Confirmed line about the free days. The app keeps the ✕ (D323), the renewal terms line, "Terms · Privacy · Restore" and the store-driven confirmation line the owner added for App Store review (9487e33d). The rest of each board is the frame's.

**D32 · Every MonoText run follows the frame's line breaks.** D13's table applied only where a screen used `WrapText` with a known width. `MonoText` now measures its own box and, when the frames drew that run broken at that width, lays it out on the frame's lines with D23's slack; a paragraph with a 700 run inside it ("…at once. **Start with this.**") is one run, keyed by its whole text (`gen-wraps.mjs` now reads such paragraphs as one run instead of reading their inline spans as runs of their own). With the text made larger in Settings the table is not used and the platform wraps (D22).

**D33 · Which answers a harness board shows.** Each questionnaire frame draws its own picks; `src/content/onboardingFunnel.ts` records them (`drawnSelected`), and the harness gives each question board that answer (`__ONB_ANSWERS`, which `welcome.tsx` already reads in mock builds). The tail frames draw a man whose three signals are "Late at night", "Home alone" and "Phone in bed" (the pills on `25 · Where We'd Start`), so the tail boards are opened with those three triggers; everything else is the mock's sample answers.

**D34 · Copy the bundle did change is the bundle's.** Under D28's rule, where `Vici UI 2` rewrote a line the app takes it: `41 · Medallion earned` is "Veni." over "Your first medallion. You started." (the "Veni" eyebrow is gone); `31 · If nothing changes` says "By age 80, if nothing changes." under the figure; `40 · The vow` drops its "Day 0, Jun 9" eyebrow and signs "Signed on Day 0, Jun 9"; `44 · Day 0` drops "Today" and its card names the lesson over "Lesson 1" beside a book; `26A`/`26A2` mark the step with two pips instead of "Step 1 of 2"; `39 · A letter from week XII` drops its eyebrow.

**D35 · The harness presses, scrolls and types.** Many frames show a board a few taps into a flow, partway down a page, or with words in a field. A simulator takes no taps from a script (and Simulator control was declined), so in a harness build only (`EXPO_PUBLIC_HARNESS=1`, development) the kit's pressable (`PressScale`) registers its handler under its accessibility label or the words it draws, `CueScrollView` its scroll view, pagers their page offsets (`HarnessPages`: Today, Score), and `TextField` its setter (`src/dev/harnessRegistry.ts`). A target lists steps — `tap:<label>`, `wait:<ms>`, `scroll:<y>`, `page:<pager>:<n>`, `type:<text>` — which `HarnessDriver` works after the route opens; every route is opened through an empty harness view so a screen already on the stack mounts afresh. The harness build also skips the launch arrivals (a milestone letter, the post, the week's report, a due check-in), which would otherwise land over whatever is being captured; each has its own route and frame. In any other build these hooks do nothing.

**D36 · Today keeps the band on the number's caption.** Today Home moves "Recovery score" from a caps line above the number to a 14/400 caption under it, and draws no band word. The app's caps line carried the owner's band (`Strong`, or `Building · N of 7 days` in the first week, 9487e33d). The caption now reads "Recovery rating · Strong" in the frame's caption style and place: the frame's layout, the owner's information, no new words.

**D37 · The frames' sample pledge in the fixtures.** The check-in and Today III frames draw "The mornings are mine again." as the man's pledge; the app never shows that sentence as anyone's pledge (D475), so the frames' state was unreachable from their seeds. The derived seeds (`<seed>-own`, `capture-seeds.mjs`) write the same sentence followed by a zero-width space: drawn identically, and the app's own rule unchanged.

**D38 · Two new check-in steps.** `Vici UI 2` adds `21D6B · Morning — One goal` ("Write one goal for today.") after the pledge and `21E5C · Night — Proud of` ("One thing you're proud of today.") after tonight's action, each a field over the notebook with Save and Skip, the dashes full. Save keeps the words and the check-in files them with the rest when it is done, as journal entries tagged with the frames' own words, "Goal" and "Proud of"; Skip clears them and moves on. A new field variant, `journal` (min 120, r20, `#1E1E1E`, padding 20 22, 18/400/28), draws them.

**D39 · What a native text field cannot match.** A `TextInput` on iOS sets its first line about a point lower than a text run of the same size and line height, wraps greedily (no `text-wrap: pretty`), and shows the platform caret only while focused. Boards with typed words therefore keep a hairline difference along the typed line; offsetting the field to hide it would be a compensating hack, so it is left and listed.

**D40 · Half-leading on tight lines.** WebKit centres a run's glyphs in its line box; when the line is tighter than the face's natural height (Lato: 1.2 × size) the glyphs sit half the deficit above where a natural line puts them. React Native on iOS only centres when the line is taller than the font's own line (`RCTApplyBaselineOffset`), so every tight run (the 56/56, 48/50, 44/52 and 60/70 figures) drew that half deficit higher than the frames: measured in the vertical text lab (`VLab`, `scripts/vici-ui-2/vlab.mjs`) as −3.67 at 48/50, −5.33 at 56/56, −1.00 at 60/70 and 0 on every line at or above natural. `halfLeading()` (theme) returns the CSS rule itself — the run moves down by the half deficit and gives it back below, so its layout box is the line box CSS gives it — and `MonoText` and `WrapText` apply it on iOS.

**D41 · Hero clearance judged by the painted art.** `Hero`'s rule for art near the bottom controls (raise it a little when it comes within 16, drop it when far closer — D320) measured the art by the designer's bounds. Redrawn cards can end well above those bounds (the clipboard's foot is at 192.8, its bounds say 210), so boards whose art cleared the controls in the frame were lifted 2pt. The rule now reads the art as painted (`HERO_PAINT_Y`).

**D42 · Urge Overview, one page in two parts.** `Vici UI 2` replaces the four-tab overview (Overview / Strength / Mood / Timing) with a single page: the busiest two hours as a heading and a line, four ruled facts, and — scrolled to, the page snaps — three cards: what helped (the SOS task's own drawing, how often, strength before → after), where (the frame's three room drawings, generated from 91B into `src/content/overviewArt.ts`), and the slips. The sentences are the frame's with the log's numbers: "Most come late at night." when the busiest two hours start between 10 pm and 1 am, "Most come between 3 pm and 5 pm." otherwise, and "5 of your 9 urges in the last 30 days came between 11 pm and 1 am."; with fewer than two urges there is no heading about where most fall. The frame's "Helped most · Walking indoors" names a category the log does not keep; the app names the task that helped ("Walk indoors for three minutes"). The facts scroll to their card; the slip rows open the relapse log; the frame's chevrons on what-helped rows lead nowhere the app has, so those rows draw the chevron and do nothing. The "30 days" in the nav is a label: the frame draws no range picker.

**D43 · The weekly report as short pages.** Opened from Report Ready the report is now the frames' five pages (91C … 91C6): the days, the urges, what helped, a line from the journal, what comes next — each left out when the week has nothing for it, and Report Ready says how many ("Jul 14–20. Five short pages."). `src/lib/weeklyStory.ts` builds them from the log in the frames' own sentences: "Seven clean days." / "Jul 14–20. Your first full week without a slip." / "Jun 30 – Jul 6. One slip, Friday at 11:52 pm. You logged it the same night." (the last clause only when the relapse was logged as happening now or earlier that day); "Three urges. You rode out all three."; "Walk indoors for three minutes helped most." / "You used it twice. Both times the urge dropped from 4 to 2." (the second sentence only in that case); "From your journal." with what he was proud of (D38) before a reflection or a goal; "Next up: In the Moment." / "Week 3 of the course opens on Monday." with "Week 3 of 12" and the owner's rating ("Rating 83, up 3" where the frame says "Score 1,240, up 12", D30). Settings still opens the register `Vici UI 2` draws there (93D: Score / Days / Urges).

**D44 · Two canvases that are not screens to build.** `Email Login (before label pass).dc.html` is the app canvas before its label pass: 164 of its 254 frames reappear in `Email Login.dc.html` (which the app is checked against), and the other 90 are the SOS and slip boards that `Vici SOS` and `Vici Relapse` replaced (D7, D19). `Lesson Illustrations v4.dc.html` is the illustrator's notes — each card a drawing, three bullets and a "Before" thumbnail — not a screen; its drawings differ from the ones the screens use, and the app draws what the screens draw (D24). Their ledger rows are SUPERSEDED with that reason; nothing in them is unaccounted for.

**D45 · Lesson copy breaks where WebKit broke it.** The reader carried a table of "Chrome's own breaks" from the previous run (`scripts/overhaul/lesson-breaks.json`), pre-breaking 289 runs before they reached `MonoText`. Measured against `Vici UI 2`'s WebKit renders some of those lines differ (L6 F13's "Done when" sentence broke after "step or" where WebKit breaks after "contact"), and a pre-broken run no longer matched the WebKit table (D32). The reader now hands each run to `MonoText` whole, and every one of the 289 is in the WebKit table; the old table is no longer generated. Lesson pages also draw each hero in the box their own frame states (`heroBox` / `box` in `src/content/lessons.ts`): thirteen long pages use a compact 117-point box, not the drawing's usual one.

**D46 · The bundle's written briefs.** `relapse-workflow.md` is a product brief for a longer post-slip flow (stop access, a reset action, the pledge, a repeat-slip branch) that asks for "slip" throughout; `Vici Relapse.dc.html` is the design drawn from it — when, what led up to it, watching again, one message, the log — and says "relapse" throughout. The canvas is the design, so the app follows it (D19); the brief's behaviour the app already has stays (the morning-after letter, an SOS session's facts carried into the record). `viz-preview.html` is empty; `task-src.json`, `taskgen-meta.js` and `taskgen-visuals.js` are the sources `sos-library.js` and `sos-viz.js` were generated from (the app ports those two, D8); `restyle-lessons.js`, `ios-frame.jsx`, `support.js`, `_bbox.js` and `image-slot.js` are the canvases' own tooling; `exports/`, `screenshots/`, `uploads/`, `ref/` and `ref-stoic/` are reference (D18).

**D47 · A scrolling column stays inside its band.** `ScrollRegion` let native content draw past its band (`overflow: visible`) so the rings at a column's edge stay whole. Where the content is taller than the band that let rows draw under the controls outside it: on Settings, which the owner's added rows (D28) make scroll at 852, "Manage subscription" ran under "Sign out". The band now clips once its content is taller than it, and still draws past its edges where the content fits — every board that fits at 393 × 852 is unchanged, and every row that uses the band was diffed again.

**D48 · Nothing behind the pledge sheet.** `21D6 · Change the pledge` paints the ground, a 0.68 black scrim and the sheet from 120 — no page behind it, where the other sheet frames (Edit name, Sign out, Profile photo) draw their page dimmed. Everything the morning check-in draws below 120 is under the sheet; its nav row is the one thing the app showed through the scrim.
